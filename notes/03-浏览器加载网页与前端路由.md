# 03 浏览器加载网页与前端路由

日期：2026-11-09

当前学习状态：

- 已理解浏览器不是只下载 HTML，还会加载资源并运行 JavaScript。
- 已初步理解多个脚本的加载和执行过程。
- 已初步理解 URL 片段与前端路由。
- 对 defer、async 和单页应用只要求形成印象，后续再通过实验巩固。

## 一、学习目标

1. 理解从输入网址到看到网页之间发生的主要过程。
2. 理解浏览器收到的 HTML 与最终显示页面的区别。
3. 理解一个网页中可以有多个 JavaScript，以及它们并非同时执行。
4. 理解脚本顶层代码、函数、条件分支和事件回调的执行时机。
5. 理解 Python `__main__` 与浏览器 JavaScript 入口的异同。
6. 理解为什么访问 `/` 后，地址栏会变成 `/#/index`。

## 二、观察到的现象

在浏览器中输入：

```text
https://www.ctfhub.com/
```

最终看到 CTFHub 首页，地址栏变成：

```text
https://www.ctfhub.com/#/index
```

但使用 Python requests 请求时，结果是：

```text
请求 URL：https://www.ctfhub.com/
最终 URL：https://www.ctfhub.com/
状态码：200
Content-Type：text/html
```

可以看到：

- Python 直接得到 200 和 HTML。
- Python 最终 URL 没有发生变化。
- Python 只打印 HTML 源代码，不会显示完整网页。
- 浏览器则继续处理资源，最终显示页面并改变地址栏片段。

## 三、浏览器加载网页的完整过程

### 1. 解析 URL

浏览器识别出：

```text
协议：https
主机名：www.ctfhub.com
端口：443（HTTPS 默认端口）
路径：/
```

### 2. 找到服务器并建立连接

如果本地没有可用缓存，浏览器需要通过 DNS 查询服务器 IP。

随后：

```text
建立网络连接
    ↓
进行 TLS 握手
    ↓
验证服务器证书
    ↓
建立 HTTPS 安全通道
```

部分连接信息可能被缓存或复用，因此不是每次访问都完整重新执行。

### 3. 请求 HTML 入口文件

浏览器发送：

```http
GET / HTTP/1.1
Host: www.ctfhub.com
```

服务器返回：

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

响应体是 HTML 入口文件。

这份 HTML 是网页的起点，但不是用户最终看到的完整运行页面。

### 4. 解析 HTML 并加载其他资源

浏览器解析 HTML 时，可能发现：

- CSS 样式文件；
- JavaScript 文件；
- 图片；
- 字体；
- 其他前端资源。

浏览器会继续发送请求加载这些资源。

因此：

&gt; 打开一个网页通常不是只有一次 HTTP 请求，而可能包含文档、样式、脚本、图片和 API 等多次请求。

### 5. 加载并执行 JavaScript

浏览器按照脚本的位置、类型和加载方式，在合适的时机下载并执行 JavaScript。

脚本可能进一步：

- 初始化前端应用；
- 注册按钮和页面事件；
- 加载其他脚本；
- 请求后端 API；
- 修改页面内容；
- 设置前端路由。

### 6. 显示最终页面

浏览器把 HTML 结构、CSS 样式和 JavaScript 运行结果组合起来，
形成用户最终看到的页面。

所以：

```text
服务器返回的 HTML ≠ 浏览器最终显示的完整页面
```

## 四、一个网页可以有多个 JavaScript

网页中的 JavaScript 没有固定数量，可能只有一个，也可能有很多个。

### 1. 内联脚本

直接写在 HTML 中：

```html
&lt;script&gt;
    console.log("这是内联脚本");
&lt;/script&gt;
```

浏览器解析到这段代码时，可以按照规则执行它。

### 2. 外部脚本

放在独立的 `.js` 文件中：

```html
&lt;script src="/js/app.js"&gt;&lt;/script&gt;
```

浏览器需要先请求并下载文件，然后再执行。

这里的文件名只是示意，不是 CTFHub 的真实文件名。

### 3. 动态加载的脚本

已经运行的 JavaScript 还可以继续加载其他脚本或模块。

因此，Burp 中看到的一些 `.js` 请求，不一定直接写在最初的 HTML 中，
也可能是脚本运行后产生的。

### 4. 文件数量不代表源代码规模

现代前端项目发布前可能进行打包：

- 开发时有很多源代码文件；
- 发布后合并成少量 `.js` 文件；
- 也可能拆成多个文件，按需加载。

所以，浏览器下载的 `.js` 文件数量，不等于项目开发时的源代码文件数量。

## 五、多个脚本是否都会执行

不能简单理解为“所有脚本同时执行，所有代码都运行一遍”。

更准确的结论是：

&gt; 被浏览器成功加载、允许执行且实际执行到的脚本，其顶层代码会执行；
&gt; 但函数、条件分支和事件回调是否执行，要看后续调用和运行情况。

### 1. 顶层代码

```javascript
console.log("脚本开始运行");
let pageName = "index";
```

脚本执行到这里时，会直接运行这些语句。

### 2. 函数定义

```javascript
function login() {
    console.log("开始登录");
}
```

浏览器执行到函数定义时，只是创建了函数，不一定马上执行函数体。

只有发生调用：

```javascript
login();
```

函数体才会执行。

因此：

```text
执行 JS 文件 ≠ 文件中的所有函数都执行一遍
```

### 3. 条件分支

```javascript
if (userIsLogin) {
    loadUserData();
}
```

只有条件成立，才会执行对应分支。

### 4. 事件回调

```javascript
button.addEventListener("click", function () {
    console.log("按钮被点击");
});
```

脚本加载时主要是注册事件处理逻辑。
只有按钮被点击，回调函数才会执行。

### 5. 没有成功执行的脚本

以下情况可能导致脚本没有正常执行：

- 文件下载失败；
- 浏览器安全策略阻止执行；
- 脚本存在语法错误；
- 前置依赖没有准备好；
- 页面在脚本执行前已经关闭或跳转。

一个脚本出错，不一定导致其他所有脚本停止，
但依赖它的代码可能随之出错。

## 六、浏览器不是“全部下载完后统一执行”

浏览器通常是一边解析 HTML，一边按照规则加载和执行脚本。

### 1. 普通脚本

```html
&lt;script src="/js/common.js"&gt;&lt;/script&gt;
&lt;script src="/js/app.js"&gt;&lt;/script&gt;
```

普通外部脚本可能让 HTML 解析暂时等待：

```text
解析 HTML
    ↓
遇到脚本
    ↓
下载并执行脚本
    ↓
继续解析 HTML
```

如果 app.js 依赖 common.js，执行顺序就很重要。

### 2. defer

```html
&lt;script src="/js/common.js" defer&gt;&lt;/script&gt;
&lt;script src="/js/app.js" defer&gt;&lt;/script&gt;
```

主要特点：

- 下载可以与 HTML 解析并行；
- 等 HTML 解析完成后再执行；
- 多个 defer 脚本通常按照声明顺序执行。

### 3. async

```html
&lt;script src="/js/a.js" async&gt;&lt;/script&gt;
&lt;script src="/js/b.js" async&gt;&lt;/script&gt;
```

主要特点：

- 下载可以与 HTML 解析并行；
- 下载完成后尽快执行；
- 多个 async 脚本的执行顺序不固定。

简化对比：

| 加载方式 | 当前需要形成的印象 |
|---|---|
| 普通脚本 | 遇到后下载并执行，执行顺序通常较明确 |
| defer | 延迟到 HTML 解析完成后执行，顺序通常明确 |
| async | 谁先准备好谁可能先执行，顺序不固定 |

多个脚本不是同时一拥而上地执行，执行顺序和依赖关系可能很重要。

## 七、JavaScript 与 Python 的相似点

### 1. 都会执行顶层代码

Python：

```python
print("程序开始")

def hello():
    print("执行 hello")

print("函数定义完成")
```

Python 会执行顶层 print，并定义 hello 函数，
但只有调用 hello() 时才执行函数体。

JavaScript 也类似：

```javascript
console.log("脚本开始");

function hello() {
    console.log("执行 hello");
}

console.log("函数定义完成");
```

浏览器会执行顶层代码并定义函数，
但只有调用 hello() 时才执行函数体。

### 2. 后续逻辑都依赖实际运行情况

无论是 Python 还是 JavaScript：

- 函数需要被调用；
- 条件分支需要满足条件；
- 某些逻辑需要等待用户操作或程序事件；
- 文件被加载不代表其中每一行都执行。

## 八、JavaScript 有没有 Python 的 __main__ 入口

没有与 Python 完全对应的统一 `__main__` 机制。

### 1. Python 的 __main__ 不是强制入口

```python
if __name__ == "__main__":
    main()
```

这段代码不是 Python 程序必须拥有的入口，
也不是 Python 最先执行的代码。

Python 仍然从文件顶部开始执行顶层代码。

`__main__` 判断主要用于区分：

- 直接运行当前文件；
- 当前文件被其他文件 import。

### 2. JavaScript 不会因为函数叫 main 就自动执行

```javascript
function main() {
    console.log("我是 main");
}
```

如果没有调用 main()，函数体就不会执行。

浏览器也不会自动在网页脚本中寻找 `__main__`。

### 3. 前端项目的 main.js 是约定，不是强制规则

前端项目中经常看到：

```text
main.js
app.js
index.js
```

它们可能是开发者约定的入口文件。

例如，某个前端应用的入口代码可能负责：

```text
创建应用
注册组件
设置路由
挂载到 HTML
启动页面逻辑
```

但 main.js 这个名称不是浏览器强制规定的，
只要 HTML 或构建工具正确引用，使用其他文件名也可以。

### 4. 两者的对应关系

| Python | 浏览器 JavaScript |
|---|---|
| 执行文件顶层代码 | 执行脚本顶层代码 |
| 函数定义不等于执行 | 函数定义不等于执行 |
| 可以有主动运行的入口文件 | 可以有项目约定的入口脚本 |
| `__main__` 区分直接运行和导入 | 没有完全对应的统一机制 |
| 可以导入多个模块 | 可以加载多个脚本和模块 |
| 通过函数调用执行后续逻辑 | 通过函数调用和事件回调执行后续逻辑 |

## 九、为什么网址会变成 #/index

变化后的 URL：

```text
https://www.ctfhub.com/#/index
```

可以拆成：

| 部分 | 内容 |
|---|---|
| 源 | `https://www.ctfhub.com:443` |
| 路径 | `/` |
| 片段 | `#/index` |

`#` 后面的内容叫 URL 片段（Fragment）。

URL 片段主要留给浏览器使用，通常不会发送给服务器。

因此，服务器收到的仍然是：

```http
GET / HTTP/1.1
```

而不是：

```http
GET /#/index HTTP/1.1
```

这里的 `/index` 是前端页面路由，
不是服务器上的独立 HTML 文件路径。

## 十、什么是前端路由和单页应用

现代网页可能是单页应用（SPA）：

&gt; 先加载一个 HTML 外壳和一套 JavaScript 应用，
&gt; 再由 JavaScript 根据路由显示不同内容，
&gt; 而不是每次切换页面都重新加载完整 HTML。

本次过程可以简化为：

```text
浏览器请求 /
    ↓
服务器返回 HTML 和前端资源
    ↓
浏览器运行前端应用
    ↓
前端发现没有指定页面片段
    ↓
默认进入 index 首页
    ↓
地址栏片段变成 #/index
    ↓
前端根据路由显示首页内容
```

因此：

&gt; 地址栏发生变化，不一定代表浏览器重新向服务器请求了一个新的 HTML 页面。

## 十一、这是不是 HTTP 重定向

本次现象主要不是典型的 301/302 HTTP 重定向。

### HTTP 重定向

```text
浏览器请求 /
服务器返回 301 或 302，以及 Location
浏览器再请求 Location 指定的新地址
```

### 本次前端路由

```text
服务器直接返回 200 和 HTML
浏览器运行 JavaScript
JavaScript 设置地址栏片段并显示首页
```

Python 请求得到 200，最终 URL 也没有变化，
说明网址变化主要发生在浏览器执行前端脚本之后。

| 对比项 | HTTP 重定向 | 前端路由 |
|---|---|---|
| 触发方 | 服务器响应 | 浏览器中的 JavaScript |
| 常见状态码 | 301、302 | 初始请求可以是 200 |
| 是否重新请求 HTML | 通常会请求新地址 | 通常不重新加载完整 HTML |
| 地址栏是否可能变化 | 是 | 是 |

## 十二、为什么 Python 没有发生同样变化

Python requests 的处理过程：

```text
GET / → 收到 HTML → 打印 HTML → 结束
```

浏览器的处理过程：

```text
GET /
  ↓
收到 HTML
  ↓
加载 CSS、JavaScript 等资源
  ↓
按照规则执行脚本
  ↓
前端应用设置 #/index
  ↓
显示首页
```

requests 不会自动：

- 渲染 HTML；
- 执行 JavaScript；
- 注册并触发浏览器事件；
- 执行前端路由；
- 自动加载页面中的所有资源。

所以 requests 只能得到 HTTP 响应，
不能直接得到浏览器执行完脚本后的完整页面。

## 十三、五段式复盘

### 1. 现象

浏览器访问 `/` 后地址变成 `/#/index`，并显示完整首页；
Python 请求只得到 HTML，最终 URL 没有变化。

### 2. 假设

网址变化可能不是服务器重定向，
而是浏览器执行前端脚本后修改了 URL 片段。

### 3. 验证

Python 请求 `/` 直接得到 200 和 HTML，没有发生重定向。

浏览器则会继续加载 CSS、JavaScript 等资源并执行脚本，
因此两者产生了不同结果。

### 4. 原理

浏览器是 HTML、CSS 和 JavaScript 的运行环境。
它不只下载 HTML，还会加载资源、执行脚本和渲染页面。

前端路由可以使用 URL 片段决定显示哪个页面。
URL 片段通常不发送给服务器，所以 `#/index` 是浏览器侧的路由信息。

多个 JavaScript 会按照各自的位置和加载方式执行，
脚本中的函数和事件回调则根据实际调用情况执行。

### 5. 防御与注意事项

进行安全测试时，不能只看浏览器地址栏。

- 没有看到地址变化，不代表没有后台 API 请求。
- 看到地址变化，不代表一定发生了 HTTP 重定向。
- 需要结合 Burp 或浏览器开发者工具观察真实请求。
- 页面加载的第三方脚本也应关注其来源和可信度。
- 不要把前端显示的内容直接当作服务器最初返回的 HTML。

## 十四、当前需要保留的核心认识

1. 打开网页通常包含多次 HTTP 请求，不只是请求一份 HTML。
2. 浏览器是一边解析 HTML，一边按规则加载和执行脚本。
3. 一个网页可以有多个 JavaScript，它们不是同时执行。
4. 执行脚本不代表文件中的所有函数都会运行。
5. 函数调用、条件分支和事件回调各有不同的执行时机。
6. JavaScript 没有与 Python `__main__` 完全对应的统一入口。
7. main.js 通常只是前端项目约定的入口文件名。
8. URL 片段主要给浏览器使用，通常不发送给服务器。
9. 前端路由可以改变地址栏并更新页面，而不重新加载完整 HTML。
10. Python requests 不等于浏览器，不会自动运行 JavaScript 和渲染页面。
